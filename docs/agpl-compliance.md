# AGPLv3 合规说明

> 本文档是项目内部合规操作说明，不构成法律意见。若涉及闭源、OEM、品牌授权或客户合同承诺，应咨询专业法律顾问并联系原项目方确认授权路径。

## 1. 项目来源

本项目基于 New API 修改。New API 是由 QuantumNous 维护的开源项目，并基于 One API（MIT License）开发。

## 2. 许可证

New API 使用 GNU Affero General Public License v3.0（AGPLv3）授权。本修改版在未取得其他商业授权的情况下，应继续按照 AGPLv3 的要求提供。

## 3. 免费提供给客户使用

本修改版可免费提供给客户通过网络使用。由于 AGPLv3 对网络交互场景有源码提供要求，部署方应为所有通过网络使用本系统的用户提供获取对应源码的机会。

## 4. 对应源码提供

本修改版会向所有通过网络使用本系统的用户提供对应源码。源码获取地址由环境变量 `SOURCE_CODE_URL` 配置，并通过公开页面和公开 API 展示。

## 5. 源码获取入口

源码获取入口包括：

- 登录页底部的“开源许可证与源码获取”链接。
- 登录后的侧边栏“开源许可证”入口。
- 关于页面中的“开源许可证与源码获取”卡片。
- 系统设置 / 其他设置中的“开源许可证与源码获取”卡片。
- 公开接口 `GET /api/about/open-source` 和兼容接口 `GET /api/license`。

## 6. 源码范围

源码范围包括：

- 本修改版程序源码。
- 构建脚本。
- 部署脚本。
- Dockerfile。
- 前端构建配置。
- 运行该程序所需的非敏感配置示例。
- NOTICE、MODIFICATIONS、README 和合规说明文档。

## 7. 不包含的敏感信息

源码范围不包括：

- 客户数据。
- 账单数据。
- 用户隐私数据。
- API Key。
- 渠道密钥。
- 数据库密码。
- 数据库 DSN。
- 生产环境 `.env` 文件。
- SQLite 生产库或数据库文件。
- 服务器 SSH Key。
- Docker registry 密码。
- 服务器密钥、证书私钥或其他敏感信息。
- 包含隐私数据的日志。

## 8. 归属信息保留要求

不允许移除、隐藏或弱化以下信息：

- New API。
- QuantumNous。
- One API。
- AGPLv3。
- 原项目版权声明。
- Logo 和页脚中的原项目归属信息。
- LICENSE 中的 AGPLv3 许可证文本。
- 原项目归属、许可证和品牌声明。

## 9. 闭源或 OEM 场景

如需闭源、不提供对应源码、去品牌、OEM、移除版权/归属展示，或对外宣称官方认证/官方支持，应先联系原项目方获取商业授权，并保留授权合同、发票、邮件或其他凭证。

## 10. 发布前检查清单

- `SOURCE_CODE_URL` 指向可访问的修改版源码仓库或源码包。
- `LEGAL_CONTACT_EMAIL` 可接收源码获取请求。
- 页面 `/about/open-source` 未登录可访问。
- API `/api/about/open-source` 未登录可访问。
- 页面和 API 不展示密钥、数据库连接、客户信息或服务器路径。
- `LICENSE` 文件未被修改。
- `NOTICE` 和 `MODIFICATIONS.md` 已随源码发布。
- `.env`、`.env.production`、数据库文件、日志和私钥未进入源码包。
